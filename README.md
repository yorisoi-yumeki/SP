# SP軍団シフト

SP軍団（9名のマッチングビジネスチーム）の月次シフト自動割当ツール。
「勉強会」（メイン/サブあり）と「M」（マッチングイベント、メインのみ）の
2種類のシフトを、複数ルールに基づいて自動で割り当てる。

## 公開ページ（実際に使う場所）

このツールは Claude の Artifact（`db` 機能つきの共有Webページ）として公開されている。
9名はこのリポジトリではなく、以下のリンクを開いて使う。

- 公開URL：https://claude.ai/artifact/NWExvWvfrHcwcM2T7vpt5f
- 共有範囲：オーナーの組織内のみ（Artifact自体の「共有」メニューから追加設定が必要）

## このリポジトリの役割

ソースコードのバックアップ・バージョン管理用。`source/sp-shift-maker.html` が
公開ページと同じ内容の単一HTMLファイル。修正する場合はこのファイルを編集し、
Claude Codeで同じ内容を上記Artifactへ再公開（republish）する。

```
source/sp-shift-maker.html
  ├─ 見た目・入力フォーム一式（HTML/CSS）
  └─ ロジック一式（JavaScript、無依存）
       ├─ ruleDefault()        … メンバー×日程ごとの◯/△/×判定
       ├─ runAssignment()      … バランシング（貪欲法）による自動割当
       ├─ parseScheduleBulk()  … 月間予定テキストの一括貼り付け解析
       ├─ parseM20Progress()   … M20進捗テキストの解析
       └─ subscribeWithRetry() … 共有DBの購読（エラー時は自動再接続）
```

## 経緯（前バージョンからの引き継ぎ）

前バージョン（Cowork上のArtifact）で「共有DBへの書き込みは成功するのに、
ブラウザ画面に反映されない」という不具合が発生し、原因を特定しきれないまま
Claude Codeへ引き継がれた。

原因として最も可能性が高かったのは、共有DBのリアルタイム購読
（`onSnapshot`）が仕様上「一度エラーで切断すると自動では復活しない」ことと、
前バージョンのコードがそのエラーを拾う処理を空にしていた（`function(){}`）ため、
切断に気づけないまま画面が固まっていたこと。

このバージョンでは対策として、

1. 購読エラーを検知したら画面にバナー表示し、自動で再接続を試みる
   （`subscribeWithRetry()`）
2. 操作した本人の画面は、保存の完了を待たずにその場で即座に更新する
   （楽観的更新。他の共有ツールで実績のある方式）

の2点を追加した。公開直後に実際の書き込み・読み出しを外部から確認済み。

## 業務ルール（確定仕様）

### 対象者（9名）
だいち、つよぽん、まぎー、やまぴー、よう、りん、ねぎ、とよかず、こばぴー

### 用語
- **勉強会**：メイン（担当・その回には参加できない）とサブ（参加しつつ補助）の役割がある。
- **M**：マッチングイベント。メインのみで、サブの概念は存在しない。
- **◯／△／×**：◯＝入れる（希望）、△＝できれば避けたい（優先度を下げて割当）、×＝不可（除外）。

### ルール一覧
1. よう・つよぽん：メインは同日重複不可
2. まぎー・こばぴー：2nd種別を含む日はメイン不可
3. とよかず・やまぴー：飲み会・カフェ会・食事会が単体開催の日の＋1枠のみ対象。サブには入らない
4. CLC：メインは前月からの2ヶ月連続不可（`history/clc`に自動記録）
5. Enトレ2：その月の対象者はメイン不可
6. カフェ会：メインはM20チャレンジ中の人のみ対象
7. CLC Final：3ヶ月ごと（8月/11月/2月/5月…）に食事会が改称したもの。食事会と同ルール
8. 前月同種別メイン回避：ソフトルール（必須ではない）
9. 合計バランス：勉強会メイン＋M入力数を9名で均等化（サブは別枠）
